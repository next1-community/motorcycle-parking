# NEXT1 社區機車位系統｜測試版 v0.1

本版供流程確認，非正式登記。資料存於社區 Supabase 專案的獨立 `next1_test` schema。示範演練僅存本機，與雲端分開。

## 畫面

- `#/register`：戶別登記、完整管理辦法、同意版本與時間、修改碼。
- `#/admin`：管理登入、名單鎖定、公開抽順位、依序選位、清冊匯出。
- `#/display`：公開順位、目前戶別、待確認車位、剩餘車位。
- `#/lookup`：依戶別查登記與結果。

## 2027 規則

一般戶最多一個名額；225-8F～15F最多兩個固有權利名額，所有名額同池抽順位，每次各選一格。1～3號不開放，4～62號共59格。2027不開放額外第二個車位登記／候補。

## 現場使用

同一電腦開啟管理及公開視窗，有線連接延伸螢幕。公開視窗透過 BroadcastChannel 接收本機同步，並以回應確認顯示狀態。住戶口述、管理中心輸入、覆誦核對後確認分配，再按下一位。雲端保存失敗時不前進。另一裝置僅提供定時讀取，不作為主投影方式。

## 部署

無建置依賴。GitHub Pages 從 main 根目錄發布 `index.html`。`config.js` 僅可放 publishable key，禁止放秘密金鑰。資料庫結構見 `db-setup.sql`，僅首次建立測試環境時執行，不可重複覆蓋。

## 管理與交接

網站管理登入與 Supabase Dashboard 帳號分開。網站不提供公開管理員註冊。建立 Supabase Auth 使用者並確認信箱後，再由平台管理者將其電子郵件加入私有 `next1_test.admins` 允許名單。管理員以個別帳號登入；登出清除本機 session。

交接時先增加 GitHub 與 Supabase 第二位 Owner，測試部署、登入及資料還原，最後撤除離任者權限。匯出CSV為作業清冊，不能取代資料庫完整備份。聯絡資料、秘密金鑰與備份均不進入公開儲存庫。

## 驗證

`node --test engine.test.mjs`。正式開放前仍需確認住戶端防冒用方式、資料保存期限及現場演練；選單與修改碼不代表戶別身分驗證。
